# Excel 歷史帳目匯入

記帳頁面的「Excel 歷史帳目」區塊可讀取 `財務投資總表.xlsx`，建立會員自己的網站歷史副本。原始 Excel 不會被改寫。ExcelJS 與 JSZip 只由 Node.js API 使用，不會載入手機瀏覽器。

## 操作

1. 開啟 `/dashboard/finance` →「匯入 Excel 帳目」→ 選擇正式帳本 `.xlsx`。
2. 核對分類、帳戶及必要的卡片對照。現金來源未提供帳戶時預設對應「現金錢包」；轉帳來源缺帳戶仍須自己指定銀行，系統不從備註猜測。
3. 調整對照後按「更新預覽」。查看每列狀態、來源 ID、工作表與列號，可搜尋、分頁及取消勾選。
4. 新增／更新預設勾選；疑似重複預設略過，需要人工核對；待補對照、已匯入及有錯誤的列不可勾選。狀態可篩選，篩選不清除已勾選資料。
5. 勾選核對聲明，再按「確認匯入」。確認前只讀取預覽；預覽後網站紀錄或對照改變會要求重新預覽。

每個支出、刷卡或金流 ID 在同一會員下對應固定網站 UUID。再次匯入相同 ID 與內容會略過，Excel 內容修改則預覽更新。沒有出現在本次檔案的舊帳目保留，不推斷刪除。已由 JSON 同步回匯保存的相同正式 ID 會被阻擋，仍需走原同步流程。

## 狀態與現金帳戶

綠色「可新增」、藍色「可更新」、黃色「待補對照／疑似重複」、紅色「資料錯誤」、灰色「已匯入」。待補對照會集中列出缺少的分類／帳戶／卡片，並提供「補上對照」入口。調整後須更新預覽，才可繼續匯入。受阻的列仍保留來源日期、金額、分類、付款方式與帳戶資訊，並顯示具體原因。

現金錢包是獨立付款帳戶，消費分類仍由 Excel 類別決定。既有兩個銀行的設定在讀取時補上錢包，不會改寫原設定或既有現金帳目；舊現金帳目的銀行對應仍保留。沒有推算錢包餘額、提款或銀行轉帳。

已與「總管(3代)」確認現有 v1 JSON 契約尚未接受 `accountId=cash`。歷史帳目可匯入網站；網站新建的錢包支出會保留待同步並明示原因，其他相容紀錄照常匯出。只有錢包待同步時不產生空批次，不以銀行假代現金；回匯也維持 v1 的帳戶限制。

## 範圍

| 工作表 | 處理方式 |
| --- | --- |
| 支出明細 | 個人負擔、支付方式、分類、固定支出與來源日期 |
| 信用卡交易 | 已結算與對應支出成組處理；消費只算支出一次，付款另列 |
| 資金異動 | 已定義的卡費繳款／家人代墊償還；卡片缺漏需明確對照，帳單月份保留未知 |
| 月收支 | 月收入、固定／變動消費保留彙總，與逐筆紀錄分開顯示，不相加 |
| 投資及其他工作表 | 顯示略過原因，留待後續版本 |

月收入來源沒有逐筆入帳日期，不製造薪資交易。支出來源可能缺少帳戶，舊信用卡支出可能沒有刷卡明細；保留可追溯的個人負擔，不補出刷卡日、實刷金額。點數非零、欄位錯誤、來源 ID 重複、不一致的配對或缺少必要日期會阻擋該組。

網站歷史副本提供「查看來源」與「複製新增」，修改應在 Excel 完成後重新匯入。歷史副本不再匯出為新帳，也不產生正式同步 revision/hash 或宣稱完成 Excel 寫入。原有 JSON 匯出及結果回匯協議維持不變；帳本端正式 JSON adapter 仍需另行完成。

## 實作與限制

- 上傳最多 3 MB，最多預覽 5000 來源列；一次確認最多 500 筆交易。信用卡與配對支出視為一組，實際算兩筆交易。
- ZIP 目錄、解壓大小與方法均有限制；公式只讀快取結果，不執行 Excel 公式。相容 SpreadsheetML 主命名空間前綴、ISO 日期與未格式化的 Excel 日期序號，全部在記憶體內處理。
- 會員隔離、來源追溯、版本檢查、成組連結與匯入紀錄都在資料庫交易內完成，失敗回退整次確認。
- 利用既有 FinanceEntry.sourceRefs 與 FinanceBatch 保存來源及匯入紀錄，沒有修改 Prisma 資料模型。
- 尚未在正式資料庫提交真實帳目，也尚未部署到正式網站。

## 驗證與回退

35 項測試通過：mock API 真正解析 XLSX，涵蓋重複匯入、穩定更新、過期預覽、帳戶缺漏、日期、ZIP 限制、會員隔離、配對與交易回退，以及現金錢包、舊設定相容與 v1 匯出／回匯邊界。正式帳本唯讀檢查得到 175 來源列／166 組，在測試內提供明確轉帳對照後均可解析；解析前後檔案 bytes 相同。這不是正式資料庫匯入結果。

TypeScript、scoped ESLint 與最終 Next.js 正式建置通過。完整 npm run build 重跑時，Prisma 引擎被執行中的開發服務鎖定；本次沒有資料模型修改，使用現有產生檔執行 next build。沙箱內 CSS 編譯子程序曾失敗，在核准權限下於沙箱外建置成功，未重啟服務。瀏覽器使用虛構資料驗證缺漏帳戶阻擋、對照更新、搜尋與確認門檻；桌面及 390 × 844 手機尺寸無水平溢出，沒有點擊確認匯入。畫面見 `finance-history-preview.png`。

安裝時 npm 回報專案共 34 項稽核問題（6 moderate、26 high、2 critical）；尚未逐項判定來源，未執行會改動其他依賴的 audit fix。正式建置另有 ExcelJS 間接依賴 fstream/rimraf external 提示，記錄驗證結果時需保留此限制。

程式回退只移除本次 history API／解析器／UI 與頁面接線，還原相關 schema/API 的歷史判斷及本次依賴；保留先前記帳客製化、日期選擇器與其他改動。已匯入資料需保留來源保護與排除匯出判斷，不能直接撤除後讓歷史副本變成待同步新帳；正式資料移除／回復需另行核對備份，不附自動刪除指令。

本次錢包與狀態調整可單獨回退，但若已有 `accountId=cash` 資料，必須保留讀取及排除 v1 匯出的保護，不能直接換回只接受銀行的 schema。未新增依賴或資料模型欄位。

現金與狀態調整已以虛構帳本驗證：補對照後黃色轉綠色、篩選保留勾選、錯誤仍保留來源欄位；390×844 的頁面寬度為 390、彈窗寬度 358，無水平溢出。新增記帳預設現金錢包，轉帳帳戶選項僅有銀行。沒有確認匯入或儲存測試交易。畫面見 `finance-cash-statuses.png` 與 `finance-cash-mobile.png`。
