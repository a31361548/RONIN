# 記帳 P1 修正

日期：2026-10-14。範圍限於先前稽核的三項 P1；記帳子頁與報表語意等 P2 尚未實作。

## 儲存與恢復

- 網站寫入成功後，關閉編輯視窗、保留回傳紀錄並顯示成功。清單重新讀取失敗另列提示與重新載入入口，不再要求重複新增。
- 刪除／還原、收入核對、歷史匯入與同步回匯的完成回呼亦分離寫入與讀取結果。回匯套用成功後立即關閉預覽。
- 匯出批次已建立但下載失敗時，提示下載原批次，不能將它描述為尚未建立。
- 收入核對顯示相關原批次下載與「前往批次與回匯」入口。批次狀態區分等待完整回匯、已回報未套用、已確認成功與需人工恢復。
- 只有相關批次全部已完整回報未套用、且收入沒有正式來源或衝突，才可重新核對。儲存核對建立新網站版本與 changeId，不修改或刪除原批次。
- 任一相關批次仍未回匯、需人工恢復或已確認成功時，仍保留阻擋。已成功同步且沒有新修改的收入，不再列為本地疑似重複。

## 同步限制

- 新增現金錢包支出時，在帳戶旁明示「先保存在網站，目前無法同步回 Excel」。
- 同步區明示 JSON 交換檔可以下載、正式 Excel 接收工具尚未完成；下載與網站儲存均不等於正式入帳。
- 尚未擴充 v1 交換契約，也未實作正式 Excel adapter；需人工恢復的替代回執規則仍未對齊，不解除既有封鎖。

## 可讀性與觸控

- 記帳頁及記帳彈窗採用局部樣式：主操作底色 `#ad5146` 配白字，對比 5.20:1；次要文字 `#695e57` 配 `#fffdfa`，對比 6.19:1。
- 原 12px 記帳文字提高至 14px，輸入與備註使用 16px。主要與次要操作至少 44px 高，保留鍵盤焦點。
- 共用選單說明文字、日期選擇器與彈窗關閉按鈕一併改善，其他使用這些共用元件的頁面亦會受益。確認按鈕加深為同一暖色。
- 在 320px 畫面，日格實測至少約 43.4px 寬、44px 高；年份完整呈現，選擇器沒有水平溢出。

## 驗證與限制

- API／計算 mock：48 通過、0 失敗、1 略過（正式帳本唯讀檢查需外部檔案路徑）。包含未回匯保護、完整拒絕後核對、另筆收入新版本、人工恢復封鎖及批次不變。
- 實際元件回呼 mock：2 通過，驗證儲存成功但清單讀取失敗，以及回匯成功但清單讀取失敗；不使用真正資料庫。
- 獨立 `tsc --noEmit --incremental false`（建置前）與修改範圍 ESLint 通過。Webpack 已成功編譯，但正式建置 exit 1：既有 `src/app/dashboard/(sidebar)/lists/[id]/page.tsx:12` 的同步 `params` 型別不符合 Next.js 16 的 Promise 型別。該檔沒有本次修改，正式建置尚未通過。
- 沙盒內 Turbopack 首先遇到子程序啟動錯誤，Webpack 沙盒內遇到 `.next` 建立目錄 EPERM；沿用建置授權在沙盒外執行 Webpack 後，才取得上述實際清單頁型別錯誤。未關閉型別檢查、修改依賴或啟停服務。
- 瀏覽器檢查桌面 1280px、手機模擬 320px／390px，表單及日曆無水平溢出。只打開並取消未儲存表單，沒有保存真實帳目、匯出新批次或上傳帳本。
- 未在實機 iPhone、螢幕閱讀器或正式 Excel 完整往返環境驗證。可見實帳沒有已匯出的收入，因此該恢復情境採 mock 驗證。
